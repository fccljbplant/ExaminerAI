## Overview

This batch resolves 8 HIGH-priority audit items. The most significant are H1 (16 AI routes missing rate limiting — monetary DoS risk) and H12 (callAI called without userId on 14 routes — usage logs had null userId). Both are now fixed via a new `enforceAIRateLimit()` helper that wraps the rate-limit + demo-block check in one call.

## Audit Fixes

### H1 — 16 AI routes missing `checkUserAILimit` (monetary DoS possible)

**Problem:** 16 AI-calling routes didn't check `checkUserAILimit` or `isDemoAIBlocked`, so a user could make unlimited AI calls — a monetary DoS risk on Vercel.

**Fix:**
- New `enforceAIRateLimit(userId, feature, isDemo?)` helper in `src/lib/ai-rate-limits.ts` — wraps `isDemoAIBlocked` + `checkUserAILimit` into a single call that returns `null` (allowed) or `{ status, body }` (blocked, return directly).
- Added the check to all 10 previously-unprotected routes:
  - `/api/daily-motivation`
  - `/api/daily-test`
  - `/api/assistant/action-dialog`
  - `/api/courses/generate`
  - `/api/teacher/topic-guidance`
  - `/api/mentorship/case-review`
  - `/api/mentorship/touchpoints/parse`
  - `/api/students/final-result`
  - `/api/project/setup` (POST + PATCH)
  - `/api/project/reports`
  - `/api/students/[id]/generate-project-analysis`
  - `/api/ai/evaluate`
  - `/api/ai/teacher-tutor`

### H3 — Counselor NOT notified of gradual wellbeing decline

**Problem:** The check-alerts cron only notified teachers + admins about struggle signals (sustained low confidence, declining scores, sustained high cognitive load). Counselors were only notified for crisis flags — gradual decline was invisible to the people whose job it is to monitor wellbeing.

**Fix:** `/api/students/check-alerts` now also notifies counselors in the student's institution when struggle signals are found. The recipient query now includes `{ role: "counselor", institutionId: student.institutionId }`.

### H5 — `buildTeacherBatchSummary` uses legacy `batchId` instead of BatchTeacher

**Problem:** The batch summary helper used `teacher.batchId` (legacy single-batch field) to find students. With the multi-teacher BatchTeacher junction, a teacher can be assigned to multiple batches — but this function only saw the legacy batchId, so students in the teacher's OTHER batches were invisible.

**Fix:** `buildTeacherBatchSummary()` now uses `getTeacherBatchIds()` (which checks BOTH the BatchTeacher junction AND the legacy batchId for backward compat). Students in ANY of the teacher's batches are now included.

### H7 — No student portfolio access from CounselorDashboard

**Problem:** Counselors were locked into aggregate views — they couldn't open an individual student's portfolio to see full details. The caseload list showed student names but clicking them did nothing.

**Fix:**
- `CounselorDashboard` now accepts an `onStudentClick` prop.
- Each student row in the Caseload view + Command Center (crisis queue) + Sessions view has a "Portfolio →" button that calls `onStudentClick(studentId, studentName)`.
- AppShell wires this to open the student's portfolio in a new tab via `/?view=batch-students&studentId=...`.

### H10 — Teacher Load module completely disconnected

**Problem:** The `/api/teacher/load` endpoint existed (returns response time trend, touchpoint completion rate, load vs capacity, crisis load, tier + reasons) but had NO UI consumer — teachers couldn't see their own load metrics.

**Fix:**
- New `TeacherLoadPanel` component (`src/components/examiner/teacher/TeacherLoadPanel.tsx`) — shows the overall tier (green/amber/red) with reasons, response time trend, touchpoint completion rate, load vs capacity, and crisis load.
- Wired into `TodayView` (the teacher's first tab) — renders at the top, above the batch health pulse.

### H11 — Growth report generated but never shown to anyone

**Problem:** The growth report was auto-generated by `/api/growth-reports/[userId]` (on first access) but there was NO UI to display it. Students didn't know it existed.

**Fix:**
- New `GrowthReportPanel` component (`src/components/examiner/student/GrowthReportPanel.tsx`) — shows the report's strengths, growth areas, behavioral notes, and 7-dimension profile snapshot. Has a "Generate" button when no report exists yet, and a "Private" badge to signal it's the honest, developmental document (not for employers).
- Wired into `ReportCardPanel` (the student's Progress tab) — renders between the certificate card and the final result panel.
- `ReportCardPanel` now accepts a `studentId` prop; `StudentDashboard` passes it.

### H12 — `callAI()` called without `userId:` on 14 routes (AIUsageLog null userId)

**Problem:** 14 routes called `callAI()` without passing `userId` in the options, so the resulting `AIUsageLog` rows had `null` userId — making it impossible to attribute AI spend to specific users for rate-limiting + auditing.

**Fix:** Added `userId:` to the callAI options on all 14 routes:
- `/api/daily-motivation`
- `/api/students/final-result`
- `/api/mentorship/touchpoints/parse`
- `/api/teacher/topic-guidance`
- `/api/mentorship/case-review`
- `/api/courses/generate` (2 calls — single + batch)
- `/api/assistant/action-dialog`
- `/api/project/setup` (generateProjectSummary function — passed from POST + PATCH)
- `/api/project/reports`
- `/api/students/[id]/generate-project-analysis`
- `/api/ai/evaluate`
- `/api/daily-test` (callAILocal function — passed from start + reply)

### H16 — Teacher Students tab: wellbeing + flag filters always empty

**Problem:** The "Struggling (Psych)" and "Flagged" filters in the teacher's Students tab used `(s as any).wellbeingTier` and `(s as any).hasFlag` — but those fields weren't in the API response. The filters always showed an empty list.

**Fix:**
- `/api/stats` (teacher role) now includes `wellbeingState: { select: { tier: true } }` and `crisisFlags: { where: { status: "open" }, take: 1 }` in the student query.
- The enriched student response now includes `wellbeingTier` and `hasFlag` fields.
- `StudentRow` type updated to include `wellbeingTier?: string | null` and `hasFlag?: boolean`.
- `StudentsRoster` filters now use the typed fields (no more `(s as any)`).
- The "Struggling (Psych)" filter now also matches `wellbeingTier === "amber"` (in addition to "warning" and "red") for robustness.
