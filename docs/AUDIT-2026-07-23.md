# Comprehensive Audit — 2026-07-23

## Summary

Full audit of the ExaminerAI codebase to fix disconnected backend-to-UI issues, identify and generate missing features, verify role-by-role UI functionality, remove orphaned code, and update documentation.

## Methodology

1. **Baseline TypeScript check** — counted all `error TS` from `npx tsc --noEmit` (baseline: 45 errors)
2. **Inventory** — listed all pages, API routes, modules, and roles
3. **Orphan detection** — cross-referenced `fetch()` / `api.get/post/put/del` calls in UI against API routes
4. **Role-flow walk** — verified each role's nav items, dashboard routing, and data access
5. **Fix application** — applied targeted fixes file-by-file, re-running `tsc --noEmit` after each batch
6. **Verification** — `npx tsc --noEmit` (0 errors), `npx next build` (success, 80 pages), `npx vitest run` (134/134 tests passing)

## Findings & Fixes

### 2. Schema sync issues

The dev (`schema.prisma`) and prod (`schema.prod.prisma`) schemas had drifted. Both are now in sync with:

- `User.projectDescription String?` (new)
- `User.projectType String?` (new)
- `ProjectTask.timeEstimate String?` (new)

Run `npm run db:push` (dev) or `npm run db:push:prod` (prod) to apply.

### 3. Portfolio optional-field crashes (17 TS errors)

`StudentPortfolioPage.tsx`, `EducationalTab.tsx`, `PsychologicalTab.tsx`, `TeacherCourseProgressView.tsx` all accessed `portfolio.weeklyTests`, `portfolio.tasks`, etc. without null checks because the API marked them optional (`?`).

**Fix:** Changed the `/api/students/[id]/portfolio` route to ALWAYS return empty arrays/objects (never `undefined`) when filtered by `dataScope`. Updated `PortfolioData` type to mark these fields as required. The `dataScope` field still tells the client what was filtered.

This eliminates ~17 TS errors at once without requiring `|| []` defensive checks at every call site.

### 4. Role-routing bugs in AppShell

The `AppShell.tsx` sidebar nav had several role-routing gaps that broke navigation for non-default roles:

| Issue | Fix |
|:---|:---|
| Admin nav items had `roles: ["admin"]` only — clicking "View As Principal" / "View As Developer" left the sidebar empty | Added `ADMIN_NAV_ROLES = ["admin", "principal", "administrator", "developer"]` and used it on all 6 admin nav items |
| Counselor was routed to `"cohort"` view but had no nav item to navigate back after switching tabs | Added `counselor` to the cohort nav item's roles |
| Guardian was routed to `"dashboard"` view (student dashboard) but had no nav items at all | Added two guardian-specific nav items: `dashboard` ("My Child") + `report-card` ("Progress") |
| `ALL_STAFF_ROLES` constant defined but never used | Removed (dead code) |
| `ALL_ROLES_WITH_SHARED` didn't include `principal`, `administrator`, `developer` — admins couldn't see shared items (AI Tutor, Course, Messages, Settings) | Added all admin roles to the shared-roles list |

### 6. Orphaned API routes removed

Cross-referenced every `route.ts` against UI `fetch()` / `api.*()` calls. Three routes had no caller anywhere:

| Removed route | Why orphaned | Replacement |
|:---|:---|:---|
| `POST /api/weekly-tests` | All weekly-test logic handled inline by `/api/ai/weekly-test` (direct `db.weeklyTest.upsert` calls) | None — callers should use `/api/ai/weekly-test` |
| `GET/POST /api/bugs` | The `Bug` model exists but no UI lists or creates bugs | Bug-tracking feature was never built out; model kept for future use |
| `POST /api/students/advance-week` | Auto-advance happens inline in `/api/ai/weekly-test` after test completion | None — `/api/ai/weekly-test` advances the week directly |

## Remaining known gaps (not blocking)

These are minor / future enhancements, not bugs:

1. **Module skeletons** — `admin`, `auth`, `communication`, `grading`, `shared`, `student`, `wellbeing` modules are still re-exports. They'll be promoted to full modules as the codebase grows.
2. **Bug model unused** — The `Bug` model exists in the schema but no UI creates or lists bugs. The model is kept for future use (was used briefly in an earlier iteration).
3. **Guardian multi-student support** — Guardian currently sees only their FIRST linked student. If a guardian has multiple children, they'd need separate accounts until this is enhanced.
4. **`react-hooks/set-state-in-effect` warnings** — 6 remaining warnings, all from the valid `setLoading(true)` + async fetch pattern. These are intentional.
5. **Schema sync** — `schema.prisma` (SQLite, dev) and `schema.prod.prisma` (PostgreSQL, prod) must be kept in sync manually. Both were updated in this audit. Consider a single schema with provider override in future.
