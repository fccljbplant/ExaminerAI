## 1. API Route Inventory

**Total route files:** 123
**Auth helpers used:** `getAuthUser` (raw JWT payload), `getCurrentUser` (full user record), `requireRole([...UserRole])`, `isStaffRole(role)`, `assertCanAccessStudent`, `demoWriteBlock(action)`.

**Role legend** (from `src/lib/rbac.ts`):
- **Public** — no auth check at all
- **Any authed** — any logged-in user (via `getAuthUser`/`getCurrentUser`)
- **Staff** — `isStaffRole(role)` = TA, Teacher, Course Coordinator, Counselor, Principal, Administrator, Demo (excludes student/pending/guardian)
- **Admin** — `ADMIN_ROLES` = Principal, Administrator, Demo
- **Self-or-staff** — `assertCanAccessStudent` — student accessing own data OR staff
- Specific roles — explicit `requireRole([UserRole.X, ...])` list

## 6. Summary of Findings

### Inventory counts

| Category | Count |
|----------|-------|
| API route files | **123** |
| Unique route handlers (method+path) | **~190** |
| UI components under `src/components/examiner/` | **~75** |
| Prisma models | **47** |
| `callAI(` call sites | **28** (across 23 unique routes + 6 lib modules) |

### Key issues found

1. **Broken `/api/seed` callers (2 sites).** Both `AdminDashboard.tsx:173` and `SystemPanel.tsx:541` call `/api/seed` with GET, but the route only accepts POST. The "Reseed Database" button is silently broken.

2. **21 orphan routes / orphan methods** with zero UI callers — including the entire `assistant/action-dialog` + `assistant/escalation/run` flow (constants exported but never imported), the entire `batches/[id]/teachers` flow, and `growth-reports`, `teacher/load`, `teacher/topic-guidance`, `project/plan`, `project/auto-report`, `course/config`, `course-outline`, `messages/outreach`, `certificates/verify`, `ai/limits`, `ai/debug`.

3. **3 AI-calling routes with NO demo-guard and NO rate-limit:**
   - `/api/daily-motivation` — any logged-in user (including demo) can hit it; could be a DoS vector.
   - `/api/students/final-result` — no demo guard, no rate limit (relies only on `assertCanAccessStudent`).
   - `/api/ai/debug` — admin-only via `requireRole`, but no demo guard or rate limit on the actual AI call.

4. **16 AI-calling routes with `demoWriteBlock` but NO `checkUserAILimit`** — listed in §4.2. These can be spammed by a single authenticated non-demo user without hitting any daily cap. Notable: `courses/generate` (8k-token calls), `project/generate-tasks` (2k-token calls × 2), `project/setup`, `project/reports`, `mentorship/case-review`, `mentorship/touchpoints/parse`, `assistant/action-dialog`, `daily-test`, `ai/teacher-tutor`, `ai/evaluate`, `ai/test`.

5. **Two duplicate feature labels for `course-gen`:**
   - `app/api/courses/generate/route.ts:217` uses `course-gen` (no rate limit)
   - `app/api/courses/upload-outline/route.ts:149` uses `course-gen` (with rate limit)
   Both increment the same `course-gen` counter in `AIUsageLog` but only one is rate-limited. A user could circumvent the cap by using the unguarded `/api/courses/generate` path.

### Suggested next actions

- **Fix `/api/seed` callers** — either add a `GET` handler to `/api/seed/route.ts` (less safe) or change the UI to use `api.post("/api/seed", {})` (safer).
- **Wire up `AI_ASSISTANT_ENDPOINTS.actionDialog` and `.escalation`** to actual UI triggers, or delete the dead constants + routes.
- **Add `checkUserAILimit` + `isDemoAIBlocked` to the 16 under-guarded AI routes** in §4.2 — especially `courses/generate`, `project/generate-tasks`, `ai/teacher-tutor`.
- **Decide on the 21 orphan routes**: implement UI, delete, or document as internal/admin-only.
- **Verify `course-gen` rate-limit bypass** — the `/api/courses/generate` route uses the same feature label as the rate-limited `/api/courses/upload-outline` but skips the cap. Either rate-limit both, or use a distinct feature label.
