Day 1 — Building Your Homepage

Learning objective: Design and build the homepage of your project using WordPress Blocks while learning the basics of good website design.

Why this matters: Visitors decide within a few seconds whether to stay on a website or leave, much like walking into a shop and forming an instant impression. A good homepage should immediately answer three questions: What is this website? What problem does it solve? What should I do next? Professional designers answer these questions on paper before touching any building tool — today starts the same way, with a quick wireframe, so you're building from a plan instead of improvising section by section inside WordPress.

What you'll do:

1. Start WAMP Server (Apache and MySQL), then open http://localhost/your-project and log in to WordPress.

2. Understand the typical structure of a professional website: Navigation → Hero Banner → About → Services → Testimonials → Call to Action → Footer.

3. Before opening the Block Editor, sketch a wireframe of this layout — a rough box diagram of where each section sits and roughly how tall it is. A pencil and paper is genuinely enough; if you'd rather work digitally, Excalidraw and Figma both have free tiers well suited to a simple one-page wireframe. The goal isn't a polished mockup, just a plan you can build against instead of designing live.

4. Navigation: keep it to only the important pages (e.g., Home, About, Services, Contact) — think of it as a book's table of contents.

5. Hero section: the first thing users see. Include a main heading, short description, button, and image (e.g., “Build Professional AI Resumes — Create ATS-friendly resumes in minutes using AI. [Get Started]”).

6. About section: explain who you are, what your project does, and why users should trust it — keep it simple.

7. Services/Features: show features as a short list rather than long paragraphs (e.g., AI Resume Builder, PDF Export, Resume Templates, Download History).

8. Call to action: every homepage should prompt visitors to act (e.g., Download Now, Register Today, Book Appointment, Contact Us).

9. Footer: typically includes copyright, social links, contact information, and a privacy policy link.

10. Using the WordPress Block Editor, build your homepage against your wireframe, section by section: navigation, hero banner, about, features, CTA, and footer.

Day 3 — Understanding Databases & phpMyAdmin

Learning objective: Understand where WordPress stores information and learn how to view your database using phpMyAdmin.

Why this matters: A database is like a school office's filing cabinets — instead of paper records for students, teachers, attendance, and exams, a database stores digital information in organized tables. MySQL is the software that stores this information for WordPress: every time someone creates an account, publishes a page, writes a blog post, or books an appointment, WordPress saves that information inside MySQL. phpMyAdmin is simply a way for humans to see that database visually, the same way File Explorer lets you browse files instead of dealing with raw storage directly.

What you'll do:

1. If using WAMP: start Apache and MySQL, then open http://localhost/phpmyadmin and log in (username: root, password: usually left empty on a default installation).

2. Locate and click your “wordpress” (or project) database in the left panel — the tables you see are simply containers of information, nothing to worry about.

3. Key WordPress tables: wp_posts (pages, blog posts, attachments — even your Home page lives here), wp_users (everyone who can log in), wp_comments (visitor comments), wp_options (site settings), wp_terms (categories and tags).

4. Click SQL at the top and run your first query:

SELECT * FROM wp_posts;

This returns every WordPress page and post.

5. Try two more queries:

SELECT post_title FROM wp_posts; -- shows only titles

SELECT COUNT(*) FROM wp_posts; -- counts the rows instead of listing them

Day 4 — Learning SQL Using LocalWP

Learning objective: Understand how SQL works and learn to retrieve information from your WordPress database using LocalWP and Adminer, without modifying your website.

Why this matters: SQL (Structured Query Language) is simply how you ask a database questions — the same way you'd ask a teacher “show me all students” and get an answer back. LocalWP manages your entire local stack automatically (browser → Apache/Nginx → PHP → WordPress → MySQL), so you never need to install any of these pieces separately.

What you'll do:

1. Open LocalWP, select your project, and click Start Site. Click Open Site to confirm your homepage loads, then click WP Admin and log in.

2. In LocalWP, open the Database tab and launch Adminer — a lightweight database tool similar to phpMyAdmin, letting you view databases, browse tables, run SQL queries, and search records.

3. Inside Adminer, click SQL Command and run each of the following queries in turn, reading the results after each one:

4. SELECT * FROM wp_posts; -- show everything in the Posts table

5. SELECT post_title FROM wp_posts; -- show only titles

6. SELECT COUNT(*) FROM wp_posts; -- count how many rows exist

7. SELECT post_title FROM wp_posts WHERE post_status='publish'; -- show only published pages (WHERE filters results, the same way “show me only Computer Science students” filters a class list)

8. SELECT post_title FROM wp_posts ORDER BY post_title; -- sort alphabetically

9. SELECT post_title FROM wp_posts ORDER BY post_date DESC; -- newest first (DESC = descending)

10. SELECT * FROM wp_posts LIMIT 5; -- show only the first 5 rows

11. Now combine two tables with JOIN. Every post in wp_posts has a post_author column that stores the numeric ID of whoever wrote it — that ID lives in a separate table, wp_users. A JOIN lets you pull both pieces of information into one result:

12. Run this in Adminer:

SELECT wp_posts.post_title, wp_users.display_name

FROM wp_posts

JOIN wp_users ON wp_posts.post_author = wp_users.ID;

-- shows each post title next to the actual name of who wrote it

13. Now try GROUP BY, which answers questions about categories of data rather than individual rows, instead of pulling every row back one at a time:

14. Run this next:

SELECT post_status, COUNT(*) AS total

FROM wp_posts

GROUP BY post_status;

-- counts how many posts fall into each status (publish, draft, trash, etc.) in one query

JOIN and GROUP BY are the two SQL skills that come up constantly in real work — JOIN because your data almost never lives in a single table, and GROUP BY because “how many of each” is one of the most common questions any business asks of its data. You'll use exactly this pattern again in Week 6 when you review your own project's data.

Day 4 — Deploying Your WordPress Website

Learning objective: Learn how to move your WordPress website from LocalWP to a live hosting server.

Why this matters: Right now, your project only exists on your own computer (Your Computer → LocalWP → WordPress → MySQL) — only you can access it. Deployment changes that path to Visitors → Internet → Hosting Server → Your Website, so anyone with your website address can visit. Hosting is essentially the “land” your website lives on so it's available 24 hours a day (popular providers include Hostinger, Bluehost, SiteGround, Namecheap, and InfinityFree for practice). A domain is simply a memorable name for your site's address, the same way people remember “google.com” instead of an IP address.

What you'll do:

1. Back up your local site first: in WordPress, go to Plugins > Add New, search for “All-in-One WP Migration,” install, and activate it.

2. Export your site: All-in-One WP Migration > Export > Export To > File. Wait for it to finish and download the backup file (e.g., my-project.wpress) — it contains your pages, images, theme, plugins, and database, everything.

3. Prepare hosting: log in to your hosting account, create a new site, and install WordPress (most hosts offer one-click installation). Log in to the new WordPress dashboard.

4. Import your site: install All-in-One WP Migration again on the live site, go to Import > Import From > File, select your .wpress file, and wait for the import to finish.

5. Log in again using the same username and password from your LocalWP project — your local project is now online.

6. Verify everything works: images, menus, the contact page, forms, your AI feature, and internal links.
